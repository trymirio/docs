---
title: "Create study"
api: "POST /studies"
description: "Create a new study"
---

Creates a study in your organization. Versive applies sensible default configuration (interview mode, messages, screen-out defaults) and merges any `config` you provide over those defaults.

<ParamField body="title" type="string" required>
  The study title.
</ParamField>
<ParamField body="description" type="string">
  Internal description of the study.
</ParamField>
<ParamField body="type" type="string" default="VERSIVE_STUDY">
  Study type. Use `VERSIVE_STUDY` (default) for AI-moderated studies.
</ParamField>
<ParamField body="mode" type="string" default="TEXT_AND_VOICE">
  Conversation mode: `TEXT_ONLY`, `TEXT_AND_VOICE`, `VOICE_WITH_PREVIEW`, or `VIDEO`.
</ParamField>
<ParamField body="access_policy" type="string" default="FULL_ACCESS">
  Controls which organization members can access the study. Use `FULL_ACCESS`, `CAN_EDIT`,
  `CAN_EDIT_SURVEY_ONLY`, `CAN_VIEW`, or `INVITE_ONLY`. This does not control participant access.
</ParamField>
<ParamField body="config" type="object">
  Study configuration overrides, merged over Versive's defaults (AI interviewer settings, branding, languages, device rules, and so on).

  Branding and languages you omit here are filled in from your organization's [study defaults](/platform/organizations-and-roles#study-defaults); values you send explicitly are kept as-is. A `lang` you send keeps its default language, and an empty `support` list still takes the organization's supported languages. A `support` list you send stays, except for a language that becomes the study's default. When the organization's default language applies, the welcome, thank-you, and screen-out messages you omit (or send as Versive's English defaults) are written in that language. When the organization has a default response limit, the new study gets that Total completes quota (returned as `quota`); change it with `PUT /studies/{id}/quotas`. Participants see a supported language only once the study is translated: after adding questions, call [Translate a study](/api-reference/studies/translate-study).

  Participant colors are `primaryColor`, `textColor` and `backgroundColor`, each a 6-digit hex value like `#18181B` (any other value returns a `422`). Leave `textColor` and `backgroundColor` out, or send an empty string, to take your organization's defaults; with no defaults set, participants see dark text on white. See [Branding](/studies/settings#branding).

  [AI interviewer](/studies/ai-interviewer) settings you omit (`interviewerPersonality`, `guidelines`, `allowQuestionRephrasing`, `questionRephrasingInstructions`, `interviewMode`) use the same defaults as a study created in the dashboard, so the interviewer may [rephrase questions](/studies/ai-interviewer#question-rephrasing). Send `"allowQuestionRephrasing": false` to have questions asked word for word.

  [Memory](/studies/ai-interviewer#memory) is set with `enableMemory` (boolean, off by default), `memoryFocus` and `memoryUsageRules` (strings, up to 300 characters each).

  The [tutorial page](/studies/tutorial-page#with-the-api) switches are set with `tutorial`: `{ enabled, requireMicCheck, showMicTest, showTimerColors, showTroubleshooting }`, all booleans. Switches you omit are off, so send `"enabled": true` to show the page. `null` counts as `false`. Unknown switches and any other value return `422`.
</ParamField>
<ParamField body="welcome_message" type="object">
  Welcome screen: `{ title, body, ctaText }`.
</ParamField>
<ParamField body="tutorial_message" type="object">
  [Tutorial page](/studies/tutorial-page#with-the-api) copy: `{ title, content, ctaText }`, where `content` is HTML. Fields you omit use the default page (header **Before you begin**, three setup tips, button **Continue**). See [Copy](/studies/tutorial-page#copy) for the length limits, the HTML that's kept, and the `422` errors. The page is only shown once `config.tutorial.enabled` is `true`.
</ParamField>
<ParamField body="thank_you_message" type="object">
  Completion screen: `{ title, body, ctaText, ctaLink }`.
</ParamField>
<ParamField body="screen_out_message" type="object">
  Screen-out screen: `{ title, body, ctaText, ctaLink }`. A default is applied if omitted.
</ParamField>
<ParamField body="folder_id" type="string">
  Folder to create the study in.
</ParamField>
<ParamField body="metadata" type="object">
  Arbitrary key/value metadata stored on the study.
</ParamField>
<ParamField body="insights" type="object">
  Insights configuration (e.g. analysis model).
</ParamField>

### Response

Returns the created study (status `201`) with fields: `id`, `title`, `description`, `metadata`, `type`, `mode`, `config`, `welcome_message`, `tutorial_message`, `thank_you_message`, `screen_out_message`, `status`, `quota`, `pause_url`, `access_policy`, and `created_at`.

<RequestExample>
```bash cURL
curl -X POST https://api.getversive.com/api/v1/studies \
  -H "Authorization: Bearer $VERSIVE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "title": "Onboarding feedback — July",
    "description": "Post-onboarding interview for new signups",
    "welcome_message": {
      "title": "Quick chat about your first week?",
      "body": "This takes about 5 minutes.",
      "ctaText": "Start"
    }
  }'
```
</RequestExample>
