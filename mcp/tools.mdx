You don't call these tools yourself — your AI assistant picks the right ones based on what you ask. This page is a reference for what's possible and what permissions each capability needs.

## Permission scopes

The consent screen shows exactly which scopes will be granted when you connect. Every client covered in the [setup guide](/mcp/setup) receives all three scopes, including connectors with no configurable scope field. If you're building your own client, you can request a read-only connection by sending an explicit `scope` with just the read scopes.

| Scope | Grants |
| --- | --- |
| `studies:read` | Read your studies, questions, groups, logic, and settings |
| `interviews:read` | Read interviews and results in your studies |
| `studies:write` | Create and edit studies, questions, groups, and logic (includes `studies:read`) |

Scopes are fixed when a client connects. To change them (for example, to add write access to a connection that was approved read-only), disconnect the client and connect it again so the consent screen runs with the new scopes.

Scopes are an upper bound, not a bypass: every request is also checked against your organization role and each study's access policy, so an agent can never see or change more than you can in the dashboard.

## Tools

### Studies

| Tool | Description | Scope |
| --- | --- | --- |
| `list_studies` | List your studies newest-first, with status filters, search, and optional activity counts | `studies:read` |
| `get_study` | Full study detail: settings, quota, branding, messages, languages, and share links | `studies:read` |
| `create_study` | Create a new study (requires an owner, admin, or creator organization role) | `studies:write` |
| `edit_study_settings` | Edit title, description, status, mode, quota (a total cap, or per-link-parameter buckets with a matching-value policy), pause URL, access policy, branding, study context, or languages | `studies:write` |
| `edit_interview_message` | Edit the welcome, thank-you, or screen-out message | `studies:write` |
| `archive_study` | Archive a study — the only removal MCP offers; reversible in the dashboard | `studies:write` |

### Questions

| Tool | Description | Scope |
| --- | --- | --- |
| `list_questions` | List questions in display order with type, group, notes, and logic flags | `studies:read` |
| `get_question_details` | One question's full configuration, media download links, logic rules, and quotas | `studies:read` |
| `add_questions` | Add questions at a position or append them to a group | `studies:write` |
| `edit_question` | Edit any question field, including its type | `studies:write` |
| `set_question_quotas` | Cap completes per option on a multiple choice question (`equals` or `includes` match, 0 closes an option); pass the full list, an empty list clears it | `studies:write` |
| `remove_questions` | Remove questions (soft delete); reports logic rules left dangling | `studies:write` |
| `reorder_questions` | Reorder all questions in an ungrouped study | `studies:write` |

### Assets

Show an image, video, or PDF beside a question. The file never travels through the MCP connection: the tool hands back an upload ticket, the file is uploaded directly, and the upload is verified before it can be attached.

| Tool | Description | Scope |
| --- | --- | --- |
| `create_asset_upload` | Start an upload. Returns `upload_page_url`, the page where you pick the file. Does not return a signed storage URL | `studies:write` |
| `complete_asset_upload` | Verify the uploaded file and report `pending`, `ready`, `rejected`, or `expired`; safe to call repeatedly. Results carry ticket state and file metadata, not a storage path or a signed media link | `studies:write` |

Attach a ready upload with `add_questions` or `edit_question` using `asset: { upload_id, layout }` (videos also take `autoplay` and `loop`); `asset: null` removes a question's media. Two more ways to set a question's media need no upload: `asset: { copy_from_question_id }` reuses another question's media in the same study, and `embedded_website_url` frames an `https` page beside the question (Figma links are refused there). Figma prototypes are not uploads: pass `figma_prototype_url` (a public prototype link) on any question except `websiteTest` and `calendar` to show the prototype beside it, or on a `prototypeTask`, where it is the task itself. See [Question media](/studies/question-media) for what participants see.

### Randomizers

Randomizers are weighted split tests: each participant is routed to exactly one arm, and an arm shows one question or one question group (or is left empty as a placeholder while you build). Use a randomized question group when you only want to shuffle order.

| Tool | Description | Scope |
| --- | --- | --- |
| `list_randomizers` | Randomizers with their arms, weights, and each arm's target question or group | `studies:read` |
| `add_randomizer` | Create a split test over existing questions or groups (2–12 arms, weights total 10,000 basis points) | `studies:write` |
| `edit_randomizer` | Rename a randomizer or replace its arms, weights, and targets | `studies:write` |
| `remove_randomizer` | Dissolve a randomizer keeping all its content (`ungroup`), or delete it with everything in its arms (`delete`) | `studies:write` |

### Recruiting panels

Panels recruit participants through Prolific or Respondent. The tools create and edit **drafts**; paying and publishing always happen in the Versive dashboard, so no tool charges money or publishes a panel.

For a study with screen-out logic, a Prolific panel must pay screened-out participants: the create tool takes a screen-out reward and the number of screen-outs to pay for, and the estimate includes that budget. Buying more screen-out slots after publishing is done in the dashboard.

| Tool | Description | Scope |
| --- | --- | --- |
| `list_panel_projects` | Recruiting panels with status and dashboard links — one study, or the whole organization when no study is given | `studies:read` |
| `get_panel_project` | One panel with its provider targeting and screener questions | `studies:read` |
| `estimate_panel_project_cost` | Advisory cost for a participant count and incentive on either provider | `studies:read` |
| `search_prolific_filters` | Search the Prolific participant-filter catalog for filter and choice ids, or list one filter's choices with `filter_id` | `studies:read` |
| `get_prolific_eligible_count` | How many Prolific participants match a set of filters | `studies:read` |
| `get_respondent_lookups` | Respondent targeting vocabularies (countries, demographics, industries, topics) | `studies:read` |
| `search_respondent_options` | Search Respondent job titles and skills | `studies:read` |
| `create_prolific_panel_project` | Create a draft Prolific panel | `studies:write` |
| `update_prolific_panel_project` | Edit a draft Prolific panel | `studies:write` |
| `create_respondent_panel_project` | Create a draft Respondent panel | `studies:write` |
| `update_respondent_panel_project` | Edit a draft Respondent panel | `studies:write` |
| `publish_panel_project` | Check a draft is ready and get the dashboard link where you pay and publish | `studies:write` |

## Prompts

Prompts are ready-made workflows. Most clients surface them in a prompt or command menu (in Claude, look under the connector's entry in the tools menu).

| Prompt | What it does |
| --- | --- |
| `get-started` | Turns your research goal into a first study: plans the questions with you, creates the study, and hands back the share link (needs `studies:write`) |
| `study-summary` | Structured research summary: themes with supporting quotes, contradictions, confidence, and follow-up questions |
| `study-insights` | Per-question thematic insights, mirroring the dashboard's Insights tab |
| `study-insights-summary` | Executive summary for stakeholders: overview, takeaways, participants, recommendations |
| `custom-insight` | Runs your own analysis question across all transcripts in a study |
| `interview-summary` | One interview: overview, participant profile, sentiment, takeaways, and quality/fraud ratings |

## Good to know

Your agent handles fetching and pagination on its own — there's nothing to configure. A few things to know:

- **Question media links expire.** `get_question_details` returns each asset's stable `url` plus a usable `download_url`. Private download links last one hour, with their UTC expiry in `download_url_expires_at`. Fetch details again to refresh a link. A `null` download URL means the private file is currently unavailable.
- **Uploading media takes two steps.** The assistant gives you `upload_page_url`; sign in, pick the file, wait for "Upload complete", then go back to the chat and reply **uploaded**. `create_asset_upload` returns that page link and does not return a signed storage URL. `complete_asset_upload` then reports whether the file is pending, ready, rejected, or expired, without a storage path or a signed media link. Review the attached file in the study editor. Files up to 50 MB; JPEG, PNG, GIF, WebP, BMP, MP4, WebM, MOV, PDF. Tickets expire after two hours.
- **Figma prototypes via MCP are embed-only.** `figma_prototype_url` embeds the prototype (share it as *anyone with the link can view*): beside an ordinary question as its asset, or as the task on a `prototypeTask`, which also records completion and duration. Goal frames, heatmaps, and per-frame descriptions still need the Figma import in the study editor. Replacing the link on a prototype task that already has a goal clears that goal.

- **Response metadata lets your agent split results and follow up.** Each interview's metadata comes back with it and as `metadata:<name>` columns in the CSV export: the [hidden fields](/studies/launch-and-sharing#hidden-fields--participant-tracking) on the participant's link (for example `source`, `segment`, or a market code) and fields from uploaded contact lists or the API, such as email. The participant's session token (the `vid` on invite links) is always left out. Sharing is off until an owner or admin turns on **Share participant metadata** in [organization settings](/platform/organizations-and-roles#ai-apps); until then, your agent receives no metadata.

- **Numbers can differ from a casual dashboard glance.** Mock and archived interviews are never exposed over MCP, and simulated interviews are always reported separately from real ones — so MCP counts reflect real research activity only.
- **A few things still happen in the dashboard.** Tree tests and conjoint questions are configured there (their text stays editable via MCP), as are Figma goal frames and heatmaps, per-language media variants, and embedded websites for `websiteTest` questions. Agents check the `get_capabilities` tool for the full list of unsupported features, each with a workaround, so they'll route around these on their own.
